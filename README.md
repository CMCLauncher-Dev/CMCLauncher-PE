CMCLauncher PE 将账号、游戏版本、资源下载、Java 运行时和触屏操作整合到同一个启动器中。首页直接展示当前账号与游戏版本，常用内容可以固定为快捷卡片，版本管理和下载入口始终容易找到。

PE 代表 Pure Edition。界面采用统一的卡片、配色和间距，页面、菜单与选中状态直接呈现，加载过程显示静态状态或实际进度。启动器不使用粒子、雨窗、液态玻璃、闪烁骨架与装饰性转场。用户操作产生的滚动、拖动、缩放以及 Minecraft 游戏画面保持正常。

## 功能与界面

### 首页与导航

底部导航包含主页、版本、下载、联机和设置。首页的账号与启动面板集中展示当前选择，可以切换账号、选择版本、进入版本设置或启动游戏。

- 版本和服务器可添加到首页，作为常用内容的快捷入口。
- 卡片支持长按调整位置、修改大小和移除；松手后直接落位。
- 横屏与宽屏采用分栏布局，窄屏保持纵向排列。
- 顶部菜单提供文件管理和任务查看入口。
- 点击反馈使用即时状态变化，主题色板与卡面颜色保持一致。

### 游戏版本

版本页集中管理多个游戏实例，并支持按原版与模组版本筛选。

- 浏览 Minecraft 版本清单，安装游戏本体及所需依赖。
- 安装 Forge、NeoForge、Fabric、Legacy Fabric、Quilt 等适配的加载器；可用选项随游戏版本变化。
- 提供 OptiFine 相关安装入口，具体支持范围以版本列表与兼容检查为准。
- 版本置顶、重命名、复制、导出与删除。
- 管理多个游戏目录，并在目录之间切换。
- 为版本配置运行环境、启动参数与游戏目录隔离。
- 管理模组、资源包、光影包、存档、截图和服务器列表。

游戏、加载器、模组与渲染器需要相互匹配。列表中出现的版本不等于所有手机都能运行该版本的全部内容。

### 账号

支持微软账号、本地离线账号和第三方认证服务器，可保存多个账号并在首页切换。账号页面提供与账号类型对应的皮肤、披风和认证管理入口。

离线账号受应用内地区判定规则约束：判定为中国大陆环境时可以直接使用；判定为中国大陆以外环境时，需要先添加微软账号。该判定使用设备环境信号，不是精确地理定位。服务器自身的账号验证要求仍然适用。

### 下载与内容管理

下载中心按游戏、模组、整合包、资源包、光影和存档分类。可检索 CurseForge 与 Modrinth 上的内容，按游戏版本和加载器筛选，并进入详情页查看兼容版本与依赖。

- 安装所选资源到对应的游戏实例。
- 导入支持的整合包，包括 CurseForge 和 Modrinth 格式。
- 收藏内容，方便再次查找。
- 查看任务阶段、实际下载进度和日志；支持的任务可取消。
- 为游戏本体和依赖选择自动、镜像或官方下载线路。

不同资源平台使用各自的分发服务。切换游戏镜像不会替换所有第三方资源的下载地址，平台限流、文件下架或访问限制也会影响下载结果。

### Java 与渲染

应用管理 Android 适配的 Java 运行时，包含 Java 8、17、21、25 的运行环境定义，并根据游戏要求选择合适的运行时。Java 管理页可查看已安装环境并导入兼容的运行时。

图形适配通过渲染器、驱动与兼容层完成，可在版本配置中选择设备支持的组合。使用光影或图形模组时，还需要匹配对应加载器、渲染器能力和 GPU 驱动。

安装新的 Java 环境不会自动解决模组依赖或图形兼容问题；排查时应结合启动日志判断。

### 操作与联机

触屏操作由虚拟按键、摇杆与布局系统提供，支持布局编辑和保存，也可使用设备支持的键鼠、手柄输入。游戏内菜单提供退出、日志和显示信息等基础功能。

联机页提供房间相关入口，服务器列表可以保存地址并连接服务器。能否加入游戏取决于网络连通性、游戏协议、模组组合和服务器认证要求。

### 文件与日志

内置文件管理器提供目录浏览、搜索、复制、移动、重命名、压缩、解压和文本编辑等功能。通过启动器打开对应版本的目录，可以减少把文件放错实例的问题。

任务菜单、游戏日志与崩溃信息用于查看当前进度和定位错误。应用同时使用前台服务和通知显示后台任务状态，实际后台存活时间仍受 Android 与设备电池管理策略影响。

## 系统要求

| 项目 | 要求或建议 |
|---|---|
| Android | 最低 Android 8.0，API 26 |
| 发布 APK 架构 | 当前 Actions 发布 arm64-v8a 包，需要 64 位 ARM Android 环境 |
| 内存 | 轻量原版建议至少 4 GB；较新版本和模组整合包建议 8 GB 或更多 |
| 存储 | 建议预留至少 4 GB，多个实例和大型整合包需要更多空间 |
| 图形能力 | 取决于所选渲染器；使用 Vulkan 相关方案需要设备和驱动提供相应支持 |
| 网络 | 首次登录、安装游戏及下载资源时需要网络 |

内存与存储数值是使用建议，不是所有版本的统一运行门槛。游戏版本、模组数量、资源包分辨率和视距都会改变资源需求。

给 Java 留出合适的堆内存即可，不要把设备全部可用内存分给游戏。Android、原生渲染器、音频与启动器也需要内存。

## 安装与更新

1. 打开 [最新发布](https://github.com/ylh440104/CMCLauncher-PE/releases/latest)，下载文件名含 `arm64-v8a` 的 APK。
2. 在系统提示中允许当前下载或文件管理应用安装 APK。
3. 安装并打开 CMCLauncher PE，等待初始组件准备完成。
4. 按实际使用场景授予通知、文件访问等权限。

应用包名为 `com.cmc.launcher.pe`。文件名与版本号以发布页为准，当前自动构建提供 Debug APK。

更新时使用相同签名的 APK 覆盖安装，通常会保留已有数据。若系统提示签名冲突，先确认安装包来源并备份游戏目录，不要通过直接卸载来试错。

初次运行需要解压 Java 和其他启动组件，耗时与设备存储速度有关。组件准备完成后会复用已安装文件；更新组件时可能再次解压。

## 第一次启动游戏

### 1. 添加账号

点击首页账号区域，进入账号管理，按需要登录微软账号或添加允许使用的其他账号。完成后回到首页确认当前账号。

### 2. 安装一个游戏版本

打开下载页的游戏入口，选择 Minecraft 版本。需要模组时，再选择适配的加载器和安装名称。首次排查设备兼容性时，可先运行一个原版实例。

### 3. 检查安装结果

进入版本页，确认实例已经出现。安装任务尚未完成时，可以从任务菜单查看进度和错误信息。

### 4. 启动

在首页选择游戏版本，点击启动。首次进入游戏还可能生成配置、解包资源或处理模组缓存。

如果启动失败，先查看本次启动日志，再调整 Java、渲染器或模组组合。保留第一次错误的信息有助于区分下载失败、运行时不匹配和图形初始化失败。

## 日常使用

### 安装模组与资源包

先选择目标实例，再从内容管理页或下载中心安装资源。模组必须同时匹配 Minecraft 版本与加载器，缺少前置依赖也会导致启动失败。

资源包、光影包和存档分别对应不同目录。启用版本隔离后，应通过版本管理页打开该实例的目录，而不是把文件一律放到共享游戏目录。

### 使用光影

根据游戏和加载器选择适配的光影支持方案，例如 Iris 或 OptiFine，再安装光影包。进入 Minecraft 后在相应的视频设置中启用。

光影效果是否可用取决于所选方案与手机驱动，成功下载光影包并不代表设备支持其中的全部图形功能。

### 选择下载线路

在设置中的外观与下载线路页面，选择自动、镜像或官方源。某个地址反复失败时，可先切换线路并查看任务日志中的具体资源地址。

### 调整主题

设置页提供内置色板、系统动态取色和自定义颜色。可导入自定义背景并调整不透明度，保持文字、按钮和内容层次清楚。动图与视频背景使用静态帧展示。

同一页面提供界面语言选项，可选择跟随系统、简体中文或英语。切换后界面立即按所选语言重新加载，重启应用后继续沿用该选择。

### 从其他设备接收实例

版本页右上角的接收入口可以接住同一局域网里电脑端发来的实例。电脑端开始发送后会显示地址和配对码，在手机上填入这两项，选择要接收的游戏版本即可。

- 传输内容为存档、模组与模组配置、资源包与光影包、截图与投影、`options.txt` 与服务器列表。
- 游戏本体和加载器不随包传输，目标版本需要已安装，且游戏版本与加载器要和发送端一致。
- 传输在局域网内直接完成，使用 TLS 加密并校验配对码，不经过第三方服务器。
- 一次发送多个实例的打包格式暂不支持接收。

### 管理实例与快捷卡片

不同模组组合建议使用独立实例。可以复制现有版本后再调整配置，或把常用版本、服务器固定到首页。删除快捷卡片只移除首页入口，删除游戏版本则会影响对应实例文件。

## 数据目录与备份

### 默认路径

普通主用户环境下，默认游戏目录为：

```text
/storage/emulated/0/Android/data/com.cmc.launcher.pe/files/.minecraft
```

`/sdcard` 通常指向同一共享存储。多用户环境、应用分身或外部存储不可用时，实际路径可能不同；以版本页显示的当前目录为准。

| 内容 | 默认位置 |
|---|---|
| 游戏版本、公共依赖和资源 | 应用外部文件目录中的 `.minecraft/` |
| 启动器日志 | 应用外部文件目录中的 `logs/` |
| 原生日志 | `logs/native/` |
| 触控布局 | 应用外部文件目录中的 `control_layouts/` |
| 联机日志 | 应用外部文件目录中的 `terracotta.log` |
| Java、启动组件、设置与账号相关数据 | 应用私有目录，由启动器管理 |

游戏目录的基础结构如下。实例隔离规则决定 `mods`、`config`、`saves` 等目录最终位于共享目录还是版本独立目录。

```text
.minecraft/
├── assets/
├── libraries/
└── versions/
    └── <实例名称>/
        ├── <实例名称>.json
        └── <实例名称>.jar
```

### 备份建议

- 重要存档先导出或复制到应用目录之外，例如 `Download` 下的独立备份目录。
- 迁移模组实例时，同时保留模组、配置、存档和启动参数。
- 备份触控布局，以便在其他设备恢复操作习惯。
- 保存日志时注意检查其中的账号信息、服务器地址与本地路径。

Android 11 及以上可能限制外部文件管理器访问 `Android/data`。优先使用应用内文件管理与导出入口。清除应用数据或卸载应用可能删除应用专属目录，应在操作之前完成备份。

## 常见问题

### PE 能运行哪一种 Minecraft？

本项目用于 Minecraft: Java Edition。游戏版本与内容按 Java 版的加载器、模组和资源格式管理。

### 为什么应用安装成功，游戏仍不能启动？

安装 APK 只代表应用能在当前系统运行。游戏还依赖合适的 Java、完整资源、兼容的加载器与图形驱动。先查看日志中最早出现的错误，再按对应类别排查。

### 应该选择哪个 Java 版本？

优先使用游戏版本元数据和加载器要求所指定的 Java 主版本。常见旧版使用 Java 8，许多中期版本使用 Java 17，较新的版本可能需要 Java 21 或 25。特殊整合包应遵循其说明；不要只按一个固定的版本分界强行替换运行时。

### 黑屏、花屏或只有声音怎么办？

记录当前游戏版本、渲染器和 GPU 信息，尝试适配设备的其他渲染方案。临时停用光影和图形模组可以帮助确认问题范围。不要一次修改多个参数，否则难以判断哪项调整起作用。

### 模组已经安装，为什么没有生效？

检查是否启动了目标实例、是否选择了正确加载器、文件是否放入该实例目录，以及前置依赖是否齐全。用于 Forge 的模组通常不能直接在 Fabric 环境运行。

### 为什么离线账号入口提示需要微软账号？

应用按设备环境判断地区。在判定为中国大陆以外且没有微软账号时，会要求先添加微软账号。若设备环境与实际所在地不一致，检查系统语言、时区等设置；服务器是否接受该账号仍由服务器决定。

### 下载长时间没有进度怎么办？

查看任务日志，区分域名连接失败、平台限流、空间不足和文件校验失败。游戏依赖下载可尝试切换线路，第三方资源则需要检查对应平台是否能访问。

### 初始解压看起来停住了怎么办？

先检查可用空间与后台限制，再查看启动器日志。大文件解压和校验可能需要时间。保留已有游戏数据，不要把清除数据作为常规的第一步处理方式。

### 如何减少游戏卡顿？

从降低渲染距离、模拟距离和资源包分辨率开始；再检查温度、后台应用和图形方案。堆内存不足时可以适当增加分配，持续增加内存并不能解决所有 GPU 或 CPU 瓶颈。

### 为什么连接不上服务器或房间？

检查游戏协议版本、模组清单、账号验证和网络可达性。局域网环境中的设备隔离、移动网络限制与服务端配置都可能影响连接。

### 更新后桌面仍显示旧图标？

先确认安装的是新 APK。部分桌面会缓存应用图标，可以重新添加快捷方式或重启桌面后查看，不需要为更新图标清除启动器的游戏数据。

## 构建

### GitHub Actions

仓库的构建入口为 [cmc_build.yml](.github/workflows/cmc_build.yml)。推送到 `main` 会自动触发，也可以在 Actions 页面使用 **Run workflow** 手动执行。

构建流程准备 JDK、Gradle、Android NDK 和 Rust Android 工具链，然后构建 arm64 Debug APK。成功后会保存 `cmc-apk` artifact，并将 APK 发布到 `latest` Release。

Actions artifact 有保存期限，长期下载请使用 [Releases](https://github.com/ylh440104/CMCLauncher-PE/releases)。对应运行记录可以用于核对提交、构建结果和日志。

### 工具链与配置来源

以下数值对应当前仓库，后续调整以构建文件为准。

| 项目 | 当前配置 |
|---|---|
| 构建 JDK | Actions 使用 JDK 21 |
| Gradle | 使用仓库 Wrapper，当前为 9.5.0 |
| Android SDK | 主模块 `compileSdk` 为 API 37、minor API 2；`targetSdk` 为 34 |
| 最低系统 API | 26 |
| Android NDK | 主应用指定 `25.2.9519653`，Rust 构建同时需要可用的 NDK 路径 |
| Rust | stable 工具链，配合 `cargo-ndk` |
| 主要配置文件 | `gradle/libs.versions.toml`、`gradle.properties`、各模块 `build.gradle.kts` |

`compileSdk` 是编译环境要求，不是手机必须具备的系统版本。

PetLib 的构建任务会检查并编译四个 Android Rust 目标，即使主应用只打包 arm64，也需要准备这些目标：

```bash
rustup target add aarch64-linux-android armv7-linux-androideabi i686-linux-android x86_64-linux-android
cargo install cargo-ndk --version 4.1.2 --locked
```

### 构建命令

下面的命令适用于已准备好 SDK、NDK、JDK 与 Rust 的构建环境，也可作为自定义 Actions 的构建步骤：

```bash
git clone --recurse-submodules https://github.com/ylh440104/CMCLauncher-PE.git
cd CMCLauncher-PE
chmod +x gradlew
./gradlew :CMCLauncher:assembleDebug -Darch=arm64 --stacktrace --no-daemon
```

APK 输出目录：

```text
CMCLauncher/build/outputs/apk/debug/
```

`-Darch` 使用以下值。除 arm64 发布包外，其他架构应根据所需运行时、原生依赖和实际设备另行验证。

| 参数 | 打包目标 |
|---|---|
| `arm64` | `arm64-v8a` |
| `arm` | `armeabi-v7a` |
| `x86` | `x86` |
| `x86_64` | `x86_64` |
| `all` | 按构建配置包含多个架构 |

需要覆盖微软 OAuth 或 CurseForge 配置时，可通过构建环境中的 `OAUTH_CLIENT_ID`、`CURSEFORGE_API_KEY` 提供。保持签名一致才能覆盖安装已有应用；不要在日志、Issue 或提交中暴露私有凭据。

## 项目结构

| 路径 | 职责 |
|---|---|
| `CMCLauncher/` | Android 主应用、版本与账号管理、下载、设置和启动流程 |
| `CMCLauncher/src/main/jni/` | JNI 与游戏启动所需的原生适配 |
| `CMCLauncher/src/main/assets/` | 运行时、启动组件及应用资源 |
| `LayerController/` | 游戏触控布局、控件状态与输入处理 |
| `InputMap/` | 输入事件和按键映射 |
| `CardGrid/` | 首页卡片布局、拖动与缩放 |
| `Guide/` | 界面引导与目标定位 |
| `ColorPicker/` | 颜色选择组件 |
| `LWJGL/` | LWJGL 适配、补丁与相关构建 |
| `Terracotta/` | 联机相关组件 |
| `PetLib/` | 角色预览及 Rust 原生渲染支持 |
| `docs/assets/` | 项目 Logo 的原始 ICO 与 PNG 资源 |
| `.github/workflows/` | 自动构建、产物上传与发布 |

Android 自适应图标、单色图标、旧版桌面图标、启动页与应用内标识使用同一份 Logo。通知栏使用基于该图形制作的单色资源。

## 反馈与贡献

提交 [Issue](https://github.com/ylh440104/CMCLauncher-PE/issues) 时，尽量提供可以复现问题的信息：

- 设备型号、Android 版本、GPU 和可用内存。
- 应用版本或对应的构建提交。
- Minecraft、加载器、相关模组和渲染器版本。
- 从哪个页面开始、执行了哪些操作、预期与实际结果。
- 与该次失败对应的启动器日志、游戏日志或崩溃报告。

界面问题可以附截图，性能问题请说明发生在点击、下载、首次启动还是游戏运行过程中。分享材料前删除账号令牌、认证地址中的私密参数和其他敏感内容。

欢迎提交修复与改进。修改应围绕明确问题，保持静态交互、一致的视觉样式和现有游戏兼容性；涉及启动、下载或数据迁移时，请说明验证范围和影响。
